## Focus on reader needs, not product features

Write about what the reader can accomplish, not what the product does. Feature-centric writing ("Acme supports X") focuses on the tool. Reader-centric writing ("You can do X") focuses on the outcome. Readers care about solving their problem, not about your feature list.

Lead with the benefit or outcome. Mention the feature as the mechanism, not the headline.

**Incorrect (product-centric, feature-focused):**

```markdown
Acme CLI supports parallel execution of up to 16 tasks. The platform
features a built-in caching layer that stores compiled assets. Our
dashboard provides real-time monitoring with customizable alerts.
```

**Correct (reader-centric, outcome-focused):**

```markdown
Run up to 16 tasks in parallel to finish builds faster. Speed up
repeated builds with the built-in cache, which stores compiled assets
between runs. Monitor your deployments in real time and set up alerts
for the metrics that matter to your team.
```

Reference: [Google developer documentation style guide — Some things to avoid](https://developers.google.com/style/some-things-to-avoid)
