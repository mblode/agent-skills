# Consolidate SEO and AEO into seo

Date: 2026-09-08
Baseline: c3f250918cd9407f19729803c9d66b63aa318cd2

## Decision

Merge `optimise-seo` and `seo-program` into `seo`. Keep one routing entry and load audit, implementation, research, brief and monitoring references only for the applicable task. `seo-audit` is too narrow for the combined capability and also names an independently installed third-party skill.

Keep the house opinions: Exact prompt figures, explicit No data, actual property and date scope, briefs rather than articles, honest product fit, existing-monitor reuse and no invented metrics. Remove false requirements for portfolio headings, DNS meta tokens, one JSON-LD block, mandatory x-default, build-time lastmod, fixed AI answer shapes and universal brand-visibility predictors. Use current primary sources with dated evidence boundaries.

The replacement has one concise hub, eleven conditionally loaded references and six authored evaluation cases. Sibling routes and the README now use seo; the collection contains 25 skills. Historical maintenance records retain their original names.

## Behavioral evidence

[Inputs and outputs](evidence/2026-09-08-seo/) preserve three fixed scenarios: a competitor-switcher brief with mismatched demand metrics; justified technical fixes versus false positives; and property-scoped monitoring with sparse data. Evaluations ran in fresh standalone Claude sessions with tools, slash commands and MCP disabled. The old arm loaded the complete two-skill baseline; the new arm loaded the complete edited skill. This tests supplied-context behavior, not autonomous progressive reference selection or native host triggering.

- The default CLI reported `claude-opus-5[1m]` for response generation and `claude-haiku-4-5-20251001` auxiliary usage. No model or effort override was supplied for this arm. Compare `none`, `old`, and `new-final`.
- A separate floor run explicitly used `haiku`, reported as `claude-haiku-4-5-20251001`. Compare `none-haiku`, initial `new-haiku`, intermediate `new-revised-haiku`, and `new-final-haiku`. Reasoning effort was not overridden.
- The default no-skill brief conflated keyword and prompt demand into a forecast range and invented an investment threshold. The old skill preserved Exact but imposed x-default and repeated speculative AI fan-out and brand-predictor claims. The final replacement preserved scope and Exact, identified all four supplied technical defects, accepted DNS/multiple JSON-LD/optional x-default, separated training from search, and rejected the mismatched property and one-click incident diagnosis.
- The initial floor run confused the competitor with the promoted product and recommended optional hreflang without a demonstrated need. A first general identity clarification was insufficient. Moving an explicit product/competitor distinction into the brief reference corrected the final floor run; it used `<product>` and did not invent Things for Windows. The final floor technical run treated x-default as optional and retained the actual defects.
- Description selection matched all 10 positive and 10 near-miss prompts against the named sibling descriptions. This is a controlled routing proxy, not a claim of 100 percent native-host invocation accuracy.

No blind human preference study, Codex-native execution, production attribution experiment or effort-level matrix was run. The outputs still contain stylistic inconsistency and occasional unsupported peripheral assumptions, such as assuming an uninspected page does not yet exist. The evidence supports this consolidation and the tested corrections, not a universal world-class certification. Six scenarios are authored; three compound scenarios were executed across the two capability tiers.

Output fixtures redact email addresses and normalize dash punctuation to satisfy repository conventions. Raw original CLI records remain in the session scratch directory. No credentials or session tokens are included. The filenames distinguish failed intermediate attempts from final runs.
